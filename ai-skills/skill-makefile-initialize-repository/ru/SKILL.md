## Последовательность действий

1. Оценить текущее состояние репозитория:

   - Убедиться, что корень проекта существует и является git-репозиторием;
   - Если это не git-репозиторий — прервать выполнение и сообщить пользователю;

2. Создать файл `.version` в корне проекта:

   - 1-я строка — начальная версия (например, `0.0.1`);
   - 2-я строка — совпадает с 1-й (обе строки должны быть одинаковыми);
   - Если пользователь указал иную начальную версию, использовать её;

3. Создать файл `CHANGELOG.md` в корне проекта:

   - Стандартный заголовок `# Changelog`;
   - Первая запись с начальной версией и текущей датой в формате YYYY-MM-DD (например, `## [0.0.1] - 2026-05-12`);
   - Под подзаголовком `### Added` — краткое описание инициализации (например, `- Initialization`);
   - Изменения в CHANGELOG.md делаются только на английском языке;

4. Создать файл `README.md` в корне проекта:

   - Только заголовок с названием проекта (имя директории);
   - Предложить пользователю дополнить содержимое (описание, использование и пр.);
   - При подтверждении — дополнить файл на том языке, на котором он был начат;

5. Предложить пользователю выполнить коммит с помощью скилла `skill-makefile-create-commit-push` с сообщением `Initialization`.
