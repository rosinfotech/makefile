## Последовательность действий

- Проект под управлением makefile содержит файл .version, который должен находиться в корне проекта и который контролирует версию проекта;

- Если проект находится под объявленным git flow (маркер `.git_flow/`), версию печатает сам флоу: `make git_flow_commit_push` или `make git_flow_seal` обновляют .version и подставляют версию в целевые файлы автоматически - ручной алгоритм ниже применяется только по явной просьбе пользователя либо в проектах без git flow;

- Структура файла .version:

  - 1-я строка - закоммиченная к настоящему моменту semver проекта;
  - 2-я строка - устанавливается версия, которая соответствует будущему коммиту;
  - Последующие строки - относительные пути к файлам, где необходимо заменить закоммиченную версию на новую:

    - Формат записи: `путь/к/файлу` - замена во всём файле, либо `путь/к/файлу:N` - замена только в строке N (когда литерал версии живёт на известной строке);
    - Замена выполняется только по точному совпадению литерала версии с границами слов: `0.30.1` не будет заменён внутри `0.30.10`;
    - Если таковых файлов нет, то версия ограничивается декларацией в данном файле;

- Если файл .version не изменялся с момента последнего коммита и 1-я строка совпадает со 2-й, при этом были внесены другие изменения в проект, то это значит мы имеем дело с необновлённой версией;

- В соответствии с данным скилом необходимо обновить версию проекта, для чего:

  - Если пользователь явно не указал, какую версию он хочет получить, то необходимо инкрементировать патч-версию, при этом:

    - Инкрементация 2-й строки файла .version осуществляется через непосредственную модификацию файла;
    - Запустите команду `make version_update` для обновления версии в файле .version;

      - Вызов команд `make ...` применительно к функционалу проекта makefile должен производиться в терминале ИИ-агентом, находясь в корне проекта;

      - Команда `make version_update` выполняет следующее:

        - Если 1-я и 2-я строки совпадают - сообщает `Information: version already up to date` и ничего не меняет;
        - Иначе подставляет новую версию в целевые файлы (записи начиная с 3-й строки, с учётом селекторов `:N`) и печатает отчёт: список заменённых мест (`path:N`) и количество подстановок;
        - Если вхождений старой версии в целевых файлах нет - сообщает `Information: no occurrences ... nothing to substitute`, при этом 1-я строка .version всё равно становится равной 2-й;
        - После подстановки копирует значение 2-й строки в 1-ю: обе строки содержат новую версию;

      - Если команда `make version_update` недоступна (отсутствует Makefile), выполните то же действие вручную: скопируйте значение 2-й строки в 1-ю и замените версию (по границам слов) в указанных файлах, соблюдая селекторы `:N`;

    - Убедитесь в том, что после вызова команды `make version_update` файл .version был обновлён, и его 1-я и 2-я строка совпадают;

  - Также по аналогии с пунктом выше, если пользователь указал конкретную требуемую версию, выполните те же действия, установив указанную версию вместо инкрементирования.
